## 当前产品方向：AI 导演工作台

HyperFrames 正从“手动搭积木”收敛为一条可继续加工的 AI 视频生产线：内容/口播进入后，由导演与素材 Agent 生成工程，在可视化时间轴中人工校正，最后输出成片或交付给 `video-use` 等剪辑流程。

推荐闭环：

1. 在“AI 助手”中导入口播稿、场景计划或商品素材文件夹。
2. 用网页采集和素材匹配补齐画面，在画布与时间轴中做人工校正。
3. 用“项目体检”清除阻断项，再冻结一个不可变的发布候选版本（RC）。
4. 桌面版直接渲染指定 RC；需要继续精剪时选择“导出剪辑交付包”。
5. 交付包包含 `manifest.json`、`sceneplan.json` 与拆分后的图片、视频、配音文件；时间轴保留真实入点和重叠关系。

### 长视频原片与粗剪

桌面版“AI 助手 → 长视频源素材台”可以直接引用数小时本地原片。工程只保存路径和入出点，不再把整段视频转成 Base64；可一键生成 960px 代理用于流畅审片，最终 RC 渲染仍自动使用原片。

源素材台支持连续播放、打入点/出点、把选段送入当前时间轴，以及导入通用 JSON EDL 批量建立粗剪。当前不直接解析剪映私有草稿，推荐把外部粗剪结果转成 `sources + ranges(source/start/end)` 的稳定中间格式。

源素材还可以生成整段音频波形。波形由本机 FFmpeg 读取音轨生成固定数量的峰值，不上传视频，也不依赖抽取关键画面；点击波形即可跳到对应时间。

桌面版现在内置可选择的本机 `faster-whisper` 转写层：识别已缓存模型、显示 CPU/GPU 运行方式、生成逐词时间码、持续报告进度并支持取消。同一原片、模型和语言会按文件大小与修改时间命中缓存，不重复识别；原片变化后自动失效。也可以继续导入外部 SRT/VTT。台词搜索命中后，逐词结果按真实词边界建立选段，外部字幕则使用保守的分段边界。

完成转写后可生成“可审粗剪候选”。系统只根据逐词边界和真实停顿拆句，不对内容做黑箱打分，也不会立即修改时间轴。每个候选都显示时间、台词、边界依据和“画面需人工确认”提示；用户试听后标记保留/排除，再为保留段指定“钩子、背景、核心、证明、转折、结尾”等叙事职责，并拖动式上下调整最终顺序。只有导演结构被明确确认后，片段才会按编排顺序写入时间轴，而不是机械照原片顺序排列。

结构模板只负责预填，不会替用户确认。导演 Brief 后续发生变化时，旧结构立即失效；可在不丢失审片决定的情况下同步新 Brief，再重新确认。候选、职责、顺序和确认状态都会随工程保存并进入交付索引，本次追加仍可整体撤销。

当至少两条原片已有保留候选时，源素材台会出现“跨原片故事装配”。它把不同机位、不同拍摄段落放入同一条全局故事线，允许跨素材排序、重新分配叙事职责或只从全局结构移除某段。系统会提示不同原片中高度相似的台词，但不会擅自删除；全局结构经确认且所有片段通过视觉门禁后，才会一次性按导演顺序写入时间轴，并支持整体撤销。

正式装配前还必须生成一条 720p 低码率结构预览。桌面版逐段抽取并编码，再无损拼接；每段画面标出编号、来源和叙事职责，每个音频边界应用 30ms 淡入淡出。用户可直接播放整条预览，也可对每个切点按需生成九帧检查图并标记“通过/需调整”。全部切点通过并明确确认整条预览后，正式装配按钮才会开放。结构变化会使旧预览自动失效；相同结构再次生成时复用本机缓存。

切点标记“需调整”后可直接进入修订闭环：逐词候选允许把前段出点或后段入点安全增减 50ms，也可交换切点前后两个片段。全局列表支持搜索尚未使用的保留候选并替换当前位置，替换不会改变源素材的审片结论。SRT、人工动作或缺少逐词时间码时不会开放伪精确微调。修订会清除旧视觉结论、结构确认和预演凭证；重新生成预览时使用片段级缓存，只编码实际变化的片段。

全局结构还可以冻结为不可变的“方案 A、方案 B……”：每个方案保存片段来源、顺序、职责、精确入出点、预演凭证和一条可选的导演理由。两个方案可比较新增、移除、换位、职责变化、切点变化、位置替换、总时长和来源数量。恢复方案前会验证所有候选仍然存在且保持“保留”状态；恢复只重建全局结构和对应入出点，不修改源候选的保留/排除结论，不删除正式时间轴，并要求重新完成受影响的视觉检查、结构确认和预演。

两个带有效预览的方案可以进入导演选版：界面并排播放 A/B，可同时播放或暂停、按相对进度同步，也可一键跳到两个方案共同的“钩子、背景、核心、证明、转折、结尾”等叙事位置。选版必须同时填写胜出理由和另一个方案的淘汰理由。胜出方案不会自动覆盖时间轴；必须明确恢复、重新确认并正式装配。项目体检会阻止“未选版、胜出方案已失效、当前结构不是胜出方案、胜出方案尚未装配”等状态进入 RC。冻结后的 RC 会绑定胜出方案 ID、名称、理由和选定时间，交付包继续携带完整选版记录。

胜出方案正式装配后可从选版区导出“精剪交接包”。桌面端会在写文件前重新验证每条原片的存在性、大小、实际时长与所有切点，并计算 SHA-256 首尾 1MB 快速指纹；任何素材离线、错版或切点越界都会中止。交接包包含机器可读 `edl.json`、`timeline.otio`、`timeline.fcpxml`，人工核对 `clip-list.csv`、成片时间线 `timeline.srt`、源路径表、胜出理由、校验报告和剪映操作说明，不复制或改写数小时原片，也不依赖剪映易变的私有草稿格式。

外部精剪后可把修改过的 `edl.json`、`timeline.otio` 或 `timeline.fcpxml` 导回选版区。系统先对比原胜出方案，列出删除、换位、边界、职责和时长变化；用户确认后才保存为新的不可变派生方案。工程内新增片段进入来源、边界、九帧视觉和叙事职责审核，原胜出方案和当前时间轴都不会被覆盖。来源版本不符、素材路径变化、工程外素材、重复片段、切点越界或切进逐词转写词语内部时，回写会被阻止；派生方案仍需恢复后重新完成视觉检查、结构预演和导演选版。FCPXML 首版采用 1.10 的线性主故事线范围，遇到间隙、重叠、转场、连接片段或其他未支持结构会明确拒绝，不静默压平。

保留片段还必须通过按需视觉检查：只针对当前候选生成 3×3 接触表，三行分别检查入点、正文中部和出点，每组包含前/中/后三帧，并配合该时间窗的局部波形。检查图缓存在桌面应用数据目录，不写进工程；工程只保存“通过/需调整”的结论。未通过视觉检查的保留片段不能批量追加。逐词候选可安全增减 50ms 边界余量，调整后必须重新检查；只有 SRT 分段时间码时不会假装能做逐词微调。

没有台词的动作由用户在源播放器亲自打入点/出点并保存为“普通动作、重点保留或明确不要”。普通动作进入待审，重点动作作为已确认保留候选，排除区间会压掉与它重叠的语音候选。人工动作边界若切进正在说的词，会自动向外吸附到完整词边界；两个保留片段发生重叠时，时间轴追加会被阻止，必须先排除其中一个。动作标记随工程和 `source-index.json` 保存。

原片选段默认保留现场声音。最终 RC 渲染会从原片抽取每段对应音轨，在剪切边界应用 30ms 音频淡入淡出，再按时间轴混入成片；同一原片被多次引用时只打开一次音频输入，长粗剪不会因为重复输入迅速撑爆命令行。

> “渲染 RC”和“导出剪辑交付包”需要桌面版（Electron）运行；浏览器版继续支持 JSON 与 HTML 预览导出。

### 导演决策层

“AI 助手”顶部的导演决策层保存项目的传播目标、核心受众、核心表达、语气、节奏、情绪弧线、结尾行动和视觉原则。它们属于工程数据，会进入自动保存、JSON 和剪辑交付包。

每个场景还可以指定叙事职责并锁定。锁定场景后，重新生成工程、重建配音时间轴、重建字幕和自动匹配素材都会保护该场景，避免 AI 覆盖已经确认的创作决定。高级工具中的“应用导演决策”会使用当前 brief 生成场景，而不再读取临时表单。

### 批量配音与声音驱动时间轴

生产线第二步支持“一键生成全部配音并重排时间轴”。中文项目默认使用讯飞 `x4_lingyuyan`（语速 68、音量 56、音高 48），生成后先读取真实音频时长，再同步重排场景、字幕和场景内画面。

- 文案和声音参数未变化时复用已有音频，不重复请求 TTS。
- 单项失败不会丢失其他成功结果，可只重试失败项。
- 导演锁定场景不会生成或移动，并会保留其已有素材。
- 批量重排后可执行一次性撤销，恢复生成前的完整工程。

### 项目体检、发布候选与确定性渲染

“项目体检”把缺失媒体、未生成配音、无效时间与场景重叠列为最终交付阻断项，同时提示制作风险和导演一致性问题。问题可直接定位到时间轴；字幕对齐与配音时长差异支持安全修复。

体检通过后可冻结 `RC-001`、`RC-002` 等不可变候选版本。当前稿会与所选 RC 比较积木、场景、时长、素材、健康度和导演决策变化。桌面版从指定 RC 逐帧渲染 MP4，显示进度并支持取消/重试；完成后同时输出 `.render-report.json`，记录 RC、画布、帧率、健康基线与成片 SHA-256。

### 场景审片决策

“AI 助手 → 场景审片决策”支持逐场标记待审、通过、修改或重做，并把批注钉在具体时间点。通过会同时锁定场景；修改和重做会解锁场景，并作为项目体检阻断项，防止未改完的内容被错误冻结为新 RC。

审片状态和批注属于工程数据，会进入自动保存、JSON、RC 快照、版本差异与剪辑交付包。已解决批注不会删除，而是保留为可追溯的审片记录。

### RC 可追溯交付

发布候选面板现在可直接导出指定 RC 的交付包。渲染完成后，MP4、渲染报告、SHA-256 和完成时间会写回该 RC 的持久记录，重启后仍可继续导出。

完整 RC 交付包包含：

- `release.json`：RC 身份、健康基线、审片汇总和最终成片哈希。
- `manifest.json` / `sceneplan.json`：冻结时间轴、导演决策和完整时间点批注。
- `final/`：与该 RC 匹配的最终 MP4。
- `reports/`：对应的渲染报告。
- `images/`、`videos/`、`audio/`：可继续剪辑的独立媒体文件。
- `source-index.json`：原片波形、时间码转写和媒体路径索引。

没有最终渲染时也能导出 RC 工程包，但界面会明确标记它不含最终成片。

## 核心设计：画面 = f(blocks, t)

与 HyperFrames「HTML 即视频」的契约对齐，做了三个硬性约束：

1. **确定性求值**。`src/lib/animation.ts` 的 `evaluateBlock(block, t)` 是纯函数，
   任意时间点都能算出画面。**没有用 CSS transition / 自跑 keyframes** —— 那类动画
   一旦 seek 就会漂移，无法帧精确导出。
2. **播放与渲染解耦**。播放引擎只负责把时间往前推，"播放"和"手拖播放头"走完全
   相同的渲染路径。
3. **媒体播放权归播放头**。`<video>` 不自己播，由 `VideoBlock` 根据 `localTime`
   驱动 seek/play/pause，保证音画与时间轴严格对齐。

每个积木 DOM 上都带 `data-block / data-type / data-start / data-duration`，
与 HyperFrames 「DOM 用 data-\* 声明时序」同构，为后续导出合成 HTML 留好接口。

## 数据结构

```ts
{
  id: string,
  type: 'image' | 'text' | 'video' | 'spotlight' | 'glassui' | 'chart' | 'scrollstory' | 'subtitle',
  name: string,
  props: {},              // 类型专属参数
  animation: {            // 入场动画声明
    type, duration, delay, easing, direction, distance, from
  },
  position: { x, y },     // 合成坐标（1920×1080 基准）
  start: number,          // 时间轴入点（秒）
  duration: number,       // 持续时长（秒）
  layer: number,
  visible: boolean,
  locked: boolean
}
```

> `start` 是在原始约定上补的一个字段 —— 没有它，Timeline 无法表达"第几秒出现"。

## V2.1 新增：5 个高级积木（独立组件，保持架构，未重构）

全部走已有的「积木组件 + BlockRenderer 套壳 + 工厂 + store」模式，新增类型与现有
`evaluateBlock` 时间驱动求值 / 图层 / 时间轴完全兼容：

| 积木 | 类型 | 说明 | 关键参数 |
| --- | --- | --- | --- |
| **SpotlightBlock** | `spotlight` | 径向渐变在画面上挖一个亮洞、其余压暗，引导视线 | 半径 / 羽化 / 暗度 / 染色 |
| **GlassUIBlock** | `glassui` | 玻璃拟态卡片，`backdrop-filter` 模糊其下方内容 | 尺寸 / 圆角 / 模糊 / 底色 / 描边 |
| **ChartBlock** | `chart` | SVG 柱状 / 折线图，数据来自逗号分隔字符串 | 类型 / 数据 / 颜色 / 标题 / 网格 |
| **ScrollStoryBlock** | `scrollstory` | 一段文字按 `localTime × speed` 匀速上滚，故事化字幕 | 文本 / 字号 / 速度 / 背景 |
| **SubtitleBlock** | `subtitle` | 底部居中的字幕条，带半透明底衬（文本型，auto 高度） | 文本 / 字号 / 底衬 / 内边距 |

设计要点：
- **仍是时间驱动、可 seek**。尤其 `ScrollStoryBlock` 的滚动偏移 = `frame.localTime × speed`，
  不是 CSS 自跑动画，拖播放头 / 逐帧导出都不会漂移（与 V1 的硬约束一致）。
- **GlassUI 的毛玻璃**依赖浏览器实时合成 `backdrop-filter`，需叠在视频 / 图片等
  背景内容之上才看得到磨砂；导出成静态帧时这一层模糊需用离屏快照还原（已知边界，未做）。
- 每种积木都自带合理的默认尺寸与入场动画，加完即可在右侧 Inspector 调参、在 Timeline 看效果。

## 已知边界

- 只有入场动画，没有出场动画和关键帧。
- 没有撤销重做。
- 浏览器版只导出 HyperFrames HTML；桌面版可从冻结的 RC 直接生成 MP4 与渲染报告。
- 大体积视频以内联数据保存，工程 JSON 和 HTML 文件也会相应变大。
