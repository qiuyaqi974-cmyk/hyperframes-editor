# 可审查视觉理解试版

本阶段在本地画面索引之后增加“视觉候选”，目标是减少人工从零填写动作语义的成本，不把模型输出当成事实或剪辑决定。

## 工作方式

1. 原片仍先在本机完成变化检测和代表帧提取。
2. 用户逐张选择截图；快捷选择最多取前 6 或前 12 张。
3. 界面在请求前显示将发送的图片数量、模型和内容边界。用户必须明确确认。
4. 用户可选择“截图 + 相同时间窗口播”或“仅截图”。桌面主进程只把所选的 320px JPEG 和用户启用的口播文字交给在线或本机视觉提供方；整段视频、其他截图和工程数据不发送。
5. 模型返回单帧候选，以及可选的跨帧状态变化候选。口播被标记为不可信素材文本，不能作为画面事实或模型指令。
6. 候选只保存在当前界面会话。用户必须回看对应原片时间窗，可修改字段并确认描述与边界，之后才通过现有人工入口写入动作索引。

## 配置与预算

- 桌面运行环境使用 `OPENAI_API_KEY`；可用 `OPENAI_VISION_MODEL` 覆盖默认模型 `gpt-4o-mini`。
- 单次限制 1–12 张 JPEG，总数据 URL 不超过 8 MB；单个时间窗口播最多 4,000 字符。
- 更改截图选择后，旧的上传确认和候选立即失效。
- 切换是否发送口播文字时，旧上传确认、候选和补帧结果全部失效，必须从第一次分析重新开始，避免两轮复核使用不同输入上下文。
- 这条视觉链路只在 Electron 主进程读取 API 密钥，不通过 preload 把密钥返回给页面。

### 请求负载预览

每次确认前，界面会显示实际待发送的截图数量、JPEG 解码字节数、对应口播字符数和首尾时间窗跨度。补帧第二轮在单独确认前也显示同样的负载摘要。

关闭“发送所选截图时间窗内的口播文字”后，所有送入模型的 `transcript` 字段为空，负载预览明确显示 0 字和“未发送”。原片索引界面仍可在本机显示已有口播，便于人工判断是否需要开启；显示不等于上传。

当前面板会话还会累计已发起模型请求的次数、图片数、图片字节和口播字符。请求一旦交给模型桥就计入，因此网络或模型随后报错也不会低估潜在用量；关闭面板后不持久化。在线与本机模式使用相同的透明统计，但本机模式仍只把负载发送到显式配置的回环端点。

用户可以设置本次面板会话的请求次数、累计图片数和累计图片容量上限。默认分别是 10 次、60 张和 20 MB；请求范围限定 1–100 次、图片范围 1–1,200 张、容量范围 1–512 MB。初次分析和补帧复核在调用模型前使用同一预算检查，预计超过任一项就阻止并列出原因；调整预算后仍需沿用原有发送确认门禁。

生成本地画面索引后，可以使用“按剩余预算选择”。它最多选择 12 张且不会超过当前会话剩余图片额度：额度为 1 时优先时间中部附近的本地变化点；额度更高时保留首尾上下文，再按时间分散程度优先补入变化点，最后补足覆盖帧。该操作只改变勾选状态，不读取额外媒体、不发送截图，也不替代发送确认。用户仍可手动增删选择。

只要已经勾选截图，负载区会把原片起点、全部已选截图时间和原片终点放在同一时间轴上，显示其中最长的“证据点空档”。如果该空档内还有未选的本地代表帧且当前少于 12 张，可一键补选最接近空档中点的一张；补选仍只改变本地勾选，并清除旧预检与发送确认。空档只表示这段时间没有被当前截图直接观察，不能证明其中发生或没有发生动作，也不替代回看原片。

也可以保留当前手动选择，按当前会话剩余图片预算一次补齐。系统每轮试算所有未选代表帧，加入能让“最大证据点空档”最小的一张，直到达到剩余预算允许的总张数、12 张单次上限或没有更多本地代表帧；执行前显示补齐后的张数、预计最大空档，以及将增加的 JPEG 字节和口播字符。该计划不自动替换用户已经选择的截图，不读取新帧，也不以相似度或模型结论决定内容价值。

若不希望用满剩余图片额度，可设置 1–600 秒的“证据最大空档目标”，默认 30 秒。目标补齐沿用同一逐轮试算，但当前最大空档降到目标值后立即停止；如果剩余额度、12 张单次上限或现有代表帧不足，按钮会显示实际预计只能达到的空档，不把目标值伪装成保证。目标只控制本地选择计划，不改变模型、上传范围、预算额度或正式发送门禁。

当目标方案和用满预算方案都可执行时，界面分别计算并标注两套方案将增加的图片张数、JPEG 解码字节和口播字符。目标方案达到空档目标后提前停止，因此它的负载不会借用用满预算方案的数字；统计仍不换算 Token、费用或质量收益。

目标旁会持续显示可达性：当前已达到、预计补选若干张后可达到，或计划执行后仍无法达到。没有可执行补选时进一步区分“当前会话剩余图片额度不足”“本地索引中没有更多可补选代表帧”和“现有代表帧无法进一步缩小空档”，避免把按钮消失误解成已经达标。该诊断随选择、目标和会话剩余额度实时重算，不调用模型。

若现有代表帧按当前预算规划后仍达不到目标，可在当前最大证据空档内本地补抽 2–6 张。补抽只让 FFmpeg 读取该空档的起止区间，不重新扫描整段原片，也不调用视觉模型；新帧使用独立编号加入当前截图列表，保持原有选择不变，且不会自动勾选或计入模型会话用量。用户可先查看、回看，再手动选择或重新运行目标补齐。重新生成完整画面索引或切换素材会清除这些临时补抽帧。

临时帧在列表中明确标记为“空档局部补抽”，并可单独一键清除。清除会从当前选择中移除已勾选的临时帧，同时使旧发送确认、模型候选、分析上下文、补帧复核和重复/相似预检失效；基础画面索引及其中的选择保持不变。清除本身不读取媒体、不调用模型、不写工程。

每次局部补抽形成独立批次并记录当次空档范围。界面显示临时帧总数与批次数，可只撤销最近一批，也可清除全部；撤销最近一批不会影响更早批次。两种清理操作都沿用相同的选择和分析状态失效规则，不会把已经移除的临时帧留在待发送选择中。

批次明细会在操作前显示该批当前已选数量，以及整批加入后的总图片数、最大证据空档和新增 JPEG 解码字节/口播字符。超过单次 12 张上限时会提前标明并禁用整批选择；某批已经全选或当前完全未选时，相应的选择或取消按钮也会禁用。预览只使用本地截图和口播摘要，不估算 Token、费用或模型理解质量。

每批明细还以接触表列出全部补抽帧的本地缩略画面、精确时间点和当前选中状态。点击画面只把原片定位到该帧，旁边的勾选框可以单独加入或取消该帧；回看不会改变选择，选择操作会使旧发送确认、候选和预检失效。两种操作都不会读取新的媒体区间、发送截图或调用模型，整批与单帧选择状态会实时同步。

每个补抽批次还可主动执行一次本地相邻画面比较。系统只读取该批已经生成的缩略图，为按时间相邻的画面计算 64 位差分感知哈希距离，并标出本批距离最高的一对。这个数值只反映画面缩略图的像素结构差异，可能受字幕、亮度、裁切和运动影响，不能解释动作、语义、因果或精确变化时刻；比较不会发送图片、调用模型、改变选择或计入会话用量。

完成比较后，用户可主动把本批最高差异窗口的两端合并进当前选择。该操作保留原有选择，只补入尚未选择的端点；合并超过单次 12 张上限时整次阻止，不做部分选择。成功后沿用人工改选的状态失效规则，必须重新检查实际负载和发送确认。最高差异只是本地缩略图比较结果，这个捷径不自动发送、不调用模型，也不代表两端之间一定存在有意义的动作变化。

最高差异选帧成功后会保留一次安全撤销凭证，只记录该次实际新增、此前未选中的端点。撤销因此不会取消原有人工选择；任何后续手动改选、整批操作、批次移除或重新生成索引都会清除旧凭证，避免过期撤销误改当前选择。撤销只调整本地勾选，不删除补抽帧或调用模型。

选择按钮前会预览合并最高差异两端后实际新增的图片数、JPEG 解码字节、口播字符，以及最大证据空档的前后值。选帧成功后的安全撤销回执冻结同一组点击时快照，不随后续界面重算；这些数字用于理解本地选择和实际请求负载，不换算 Token、费用或模型理解质量。

最高差异快捷选择还会检查当前会话剩余图片张数和图片容量。任一额度放不下新增端点时，按钮暂停并分别显示所需增量和剩余额度；调整预算后可恢复。用户仍可使用逐帧勾选，真正发送前的统一会话预算门禁会再次复查，因此这里的预检不会绕过或替代正式限制。

快捷选择同时要求当前会话至少剩余一次请求、当前提供方与模型可用，并且该模型尚未达到已报告 Token 停止线。本机端点最近一次明确探测失败时也会暂停按钮并保留原始探测信息。提高请求或 Token 上限、重新探测成功、切换可用模型后会实时恢复；逐帧手动选择始终保留，下一次请求的 Token 用量仍不会被预估，正式分析前继续执行统一门禁。

最高差异只是默认提示，不是唯一可选结论。完成本地相邻画面比较后，每个非最高窗口也提供明确的“两端加入选择”操作，并在点击前显示新增图片、JPEG 字节、口播字符和最大证据空档变化。这样用户可以主动避开闪光、字幕或镜头运动造成的高像素差异，改选更符合叙事判断的窗口。任意窗口选择都复用相同的图片、请求、Token、服务可用性门禁和安全撤销；系统不会自动判断哪个窗口更有语义价值。

相邻窗口按感知哈希距离从高到低稳定编号；距离相同则按时间先后排序。选择完成后的本地回执会冻结该窗口的距离、当时在本批的排名、批内窗口总数，以及它是默认最高项还是人工改选项。后续选择变化不会重算这份回执，安全撤销仍只撤销该次新增端点。排名只描述缩略画像素结构差异，不是动作、叙事价值或模型理解质量排名。

选择非最高窗口前必须填写简短的人工改选理由，例如“最高差异来自字幕闪烁，不代表动作”。空理由不会放行，最多 200 字；默认最高项不要求理由。成功选择后，理由与当时的距离和排名一起冻结在本地回执中，之后修改输入框不会改写既有回执。理由只解释本次人工选择，不会自动改变模型提示词、动作索引或剪辑决定。

面板还保留当前会话最近 20 次差异窗口选择操作，按新到旧显示选择时间、批次与时间范围、距离/排名、默认或人工改选、理由、实际新增负载、最大空档前后值，以及“已应用”或“已撤销”状态。点击安全撤销会在同一条记录上追加撤销时间，不伪造一条新的选择。记录不保存截图、不上传、不写入工程，重新生成索引或切换素材后清空；它只证明当前界面发生过这些本地操作，不证明画面语义正确。

该会话记录可主动下载为 `hyperframes-visual-difference-decisions-v1` JSON。文件包含导出时间、素材 ID 与时长、记录数量、完整冻结记录，以及对紧凑 `records` JSON 计算的 SHA-256；不包含原片路径、截图、口播正文、密钥或端点。哈希用于发现记录段在导出后是否被改动，不是签名，也不能证明操作人身份或画面真实性。

补抽接触表、总截图列表和第二轮补帧缩略图在存在亚秒偏移时显示毫秒，例如 `0:09.001`；整秒仍保持 `0:09`。这样短动作的相邻截图不会因为整秒取整而显示成同一个时间标签。时间码只提高人工定位精度，不代表系统已经知道动作发生的精确时刻。

存在多个可选批次时，界面还会比较它们相对当前选择能缩短多少最大证据空档，并按“缩短最多、增量图片更少、增量图片字节更小、生成顺序更早”标出唯一的“覆盖收益最高”批次。如果没有任何批次能缩小当前最大空档，会明确提示；这不代表批次没有语义价值，只说明它没有改善这一个时间覆盖指标。建议不会自动选择、发送或调用模型。

批次推荐还会检查当前会话剩余图片张数和图片容量。能改善覆盖但任一额度放不下的批次不会显示为可执行建议，界面会分别说明所需新增张数/字节和当前剩余额度；用户仍可调整预算或手动选择，真正发送前的会话预算门禁会再次复查。单批明细也会保留超额提示。图片容量上限支持低至 0.01 MB、步进 0.01 MB，便于低分辨率截图的小规模本地试验。

可执行建议也要求当前会话至少剩余一次请求额度，且当前所选提供方/模型尚未达到已报告 Token 停止线。任一门禁命中时，界面说明已用请求数或具体模型停止线，并提示调整上限或切换模型；不会把其他模型的 Token 合并判断，也不会预测下一次请求用量。手动选择仍被允许，真正分析前会用同一门禁重新检查。

当前视觉提供方还必须处于已配置可用状态；本机提供方若最近一次端点/模型探测明确失败，也会暂停可执行建议并显示探测消息。完成配置、重新探测成功或切换到其他可用模型后建议实时恢复。未执行过探测不会被伪装成失败，人工仍可保留或调整本地选择，模型调用前由既有服务门禁最终确认。

找到覆盖收益最高的批次时，可在建议旁一键把该批合并进当前选择。该按钮复用整批选择的 12 张硬上限和状态失效规则，只修改本地勾选；用户仍需重新检查实际负载、重复/相似预检并明确确认发送。选择完成后系统会按新选择重新比较，不把旧建议继续显示成有效结论。

采用建议后可一键撤销刚才实际新增的选择。撤销凭证只记录该次建议加入、此前未选中的帧，因此不会取消原有人工选择；任何后续手动改选、批次移除、重新生成索引或切换素材都会清除旧凭证，防止用过期操作误改当前选择。撤销同样只发生在本地，不删除补抽帧，也不调用模型。

在撤销凭证有效期间，界面同时保留该次采用建议的覆盖与负载回执：新增选择数量、最大证据空档的前后秒数，以及新增 JPEG 解码字节和口播字符。回执来自点击时的本地实际选择快照，不在事后按变化后的界面状态重算，也不估算 Token、费用或画面理解质量。

批次明细按生成顺序显示每批的空档起止和帧数，并允许移除任意一批。移除较早批次不会删除之后生成的批次；批次序号仅表示当前列表中的生成顺序，清理后会重新连续显示，不作为持久化身份或工程证据。

每批还可整批加入或取消当前截图选择。整批加入会保留原有选择，合并后超过单次 12 张上限时明确拒绝且不做部分选择；成功选择或取消后，旧发送确认、模型候选、分析上下文、补帧复核和重复/相似预检全部失效，批次帧本身仍留在列表中供继续调整。

这些是实际输入负载，不是 token 或费用估算。不同视觉模型、图片细节策略和服务商计费方式不同，系统不会用统一换算公式给出看似精确但不可靠的金额。

## 安全边界

- 模型候选不会自动写入工程、粗剪、时间轴、版本或 RC。
- 单张截图不能可靠证明连续动作；不确定内容必须显示，并由人观看视频确认。
- 接受候选继续沿用现有来源签名、时间范围、人工确认、粗剪失效和视觉门禁。
- 当前没有自动成本换算；界面只给出本次实际图片数量和上传内容范围。

## 跨帧状态变化

- 跨帧候选必须引用按时间连续选择的 2–4 张截图，截图顺序不可跳跃、倒置或重复。
- 从第一张时间窗开始到最后一张时间窗结束，跨度最多 120 秒；更稀疏的长跨度不会形成候选。
- `state-change` 只表示前后截图能直接证明状态不同；`possible-continuation` 和 `uncertain` 必须明确显示连续性尚未证实。
- 模型必须说明可见证据和不确定性，不得把截图之间没有看到的过程、因果或镜头外事件写成事实。
- 每个跨帧候选还必须按顺序逐一评价所有相邻截图对：`visible-change` 表示两帧存在直接可见的状态差异，`possible-change` 表示证据不足，`no-visible-change` 表示没有看到明确变化。界面显示两帧的实际时间范围、证据、疑点和置信度，并允许从前一帧时间开始回看。
- “变化窗”只把变化限制在相邻证据帧之间，不声称知道区间里的具体发生时刻。补帧复核后，变化窗会使用更密的证据帧重新定位。
- 候选不能直接进入动作索引。用户必须观看第一张到最后一张之间的完整视频，可编辑描述，再明确确认动作和边界。
- 人工确认后写入的动作记录带“跨帧确认”标签，并继续使旧粗剪失效；后续仍需原有视觉、结构、预演和选版门禁。

### 局部补帧细化

跨帧候选出现状态变化或不确定性时，可以只在第一张与最后一张截图之间补抽中间帧。系统先为第二轮保留原候选引用的 2–4 张证据帧，再根据当前会话剩余图片额度补抽 2–6 张；不足 2 张补帧额度时不生成复核。补帧在本机 FFmpeg 中完成，不扫描区间外画面，也不会自动调用模型。

补充截图先显示给用户；只有再次明确确认后，原候选证据和实际补抽的中间帧才进入第二轮分析。第二轮仍受单次 12 张和会话预算约束。它可以缩小变化发生的大致范围，但相邻补充帧之间仍可能遗漏短动作，因此结果继续是待审候选。

第二轮结果会与发起补帧时保存的第一轮模型原候选对照。系统逐项比较动作、结果、连续性和变化窗判断，显示“关键结论一致”或具体分歧字段，并同时展示两轮动作、结果和置信度。比较只使用模型原始字段，不受之后的人工编辑影响；它不判断哪一轮正确，也不会自动合并或采用任何结论。

如果两轮存在分歧，候选不能直接入库。用户必须先明确确认已经核对两轮差异，并以上方可编辑的人工字段作为最终结论；这一步会使此前的完整区间确认失效，必须在最终字段和分歧处理都确定后重新确认完整区间。修改最终字段会再次清除分歧确认。

补帧缓存按原片路径、大小、修改时间、范围和截图预算隔离。原片在提取过程中变化会使操作失败，旧补帧也不会在切换素材或重新选择截图后继续使用。

## 人工确认后的证据回执

从单帧或跨帧候选确认进入动作索引时，会保存一份不含图片和口播正文的结构化回执：

- 在线或本机提供方、模型名称；
- 初次分析或补帧复核；
- 当次模型输入是否包含时间窗口播；
- 当次请求的唯一批次号、发起时间、图片数、JPEG 解码字节、口播字符、覆盖跨度、当前面板会话请求序号，以及全部送入模型的截图编号、时间和 JPEG 解码字节 SHA-256；这里的完整请求可能包含该候选没有直接引用的其他截图。同一次模型调用返回的候选共享批次号，可按批次复核。
- 模型服务响应实际提供时，保存输入、输出和合计 token；在线 OpenAI Responses 与本机 OpenAI-compatible chat 分别读取各自标准 usage 字段，服务没有返回或数据自相矛盾时明确显示“未返回”，不会用图片字节或字符数推算。
- 被该候选实际引用的截图编号、时间和时间窗；
- 模型原始提出的主体、动作、对象、结果、景别和标签；
- 跨帧连续性、可见证据、不确定性和置信度。
- 每个相邻证据帧变化窗的起止时间、判断、证据、疑点和置信度。
- 补帧前后的原始动作、结果、连续性、变化窗判断、置信度以及分歧字段。
- 存在分歧时的人工核对时间和“以人工最终字段为准”的处理结论。

动作索引本身继续保存人工最终确认后的字段。两者分开显示，因此人工修改不会改写模型原始候选，模型候选也不能覆盖人工结论。完整请求帧清单只保存编号、时间和内容指纹，不保存 JPEG；回执也不保存 API 密钥、端点地址或口播文本。指纹可用于判断两份回执是否引用相同图片字节，但不证明原片真实性、模型确实理解了图片或模型服务没有另行处理输入。

Token 数字是模型服务自行报告的请求用量，可用于观察同一提供方、同一模型下不同选帧方案的相对消耗；它不等于费用、剩余额度或独立计量证明。不同提供方和模型的计数方式可能不同，不应直接横向比较。当前会话只累计成功响应中带有效 usage 的请求，并按“提供方 ID + 模型名称”分别显示请求次数、输入、输出和合计；切换模型不会丢失已有统计，也不会把两个模型的数字相加。

会话预算可设置“单模型已报告 Token 停止线”。当前选中模型的已报告合计达到停止线后，下一次请求会在模型桥之前被阻止；提高停止线后可继续。这个门禁无法预知下一次请求的用量，因此单次请求可能把累计从停止线以下推到停止线以上；服务不返回有效 usage 时也无法按 Token 阻止。请求次数、图片数量和图片容量仍使用原有的请求前预计上限。

选择截图后可先点“本地检查重复/相似”。这一步不要求勾选上传确认，只解码当前已选 JPEG，并使用与正式发送门禁相同的 SHA-256、感知哈希和当前相似阈值；结果会同时显示完全重复与高度相似预警，以及精简建议的负载变化。预检不调用模型、不生成请求批次、不增加图片或 Token 用量、不进入请求历史，也不读取未选择的截图或原视频。选择或相似阈值改变后旧预检结果立即失效；预检无告警只表示没有命中这两类本地规则，不代表截图已经充分覆盖视频内容。

每次初次分析或补帧复核还会在本地计算所选 JPEG 解码字节的 SHA-256，并在调用模型桥前检查完全重复的图片内容。发现重复时，界面列出对应时间和完整指纹；该次尝试不计入请求次数、图片用量或请求记录。用户只有在确认这些相同画面仍有时间证据价值（例如用于证明一段时间内没有可见变化）后才能继续发送。系统不会擅自删除其中一帧；选择、模型、口播设置或重新抽帧变化后必须重新确认。

对于编码字节不同的截图，渲染进程会在本地把画面缩到 9×8 像素并计算 64 位差分感知哈希；不同 SHA-256 的帧若汉明距离不超过当前阈值，会作为“高度相似”候选列出时间与距离，并在模型桥前要求另一项明确确认。阈值属于当前面板会话设置，默认 4，可在 0–16 间调整；数值越小越严格，0 只提示感知哈希完全一致但 JPEG 字节不同的帧，完全重复 SHA-256 门禁始终独立生效。修改阈值会清除旧的相似截图确认。未确认的尝试同样不计入会话用量或请求历史；确认后会话记录、导出 JSON 和最终动作证据回执保存确认时间、实际阈值、配对帧与距离，验证器用请求帧中的感知哈希复算。感知哈希是低成本提示，可能对亮度、裁切、字幕或细小物体变化误判；它不证明两帧语义相同，也不会自动删帧。

两类预警都提供用户主动触发的本地精简建议。完全重复组保留时间较早的一帧；高度相似配对按当前时间顺序保守处理：只有较早帧仍被保留时才移除对应较晚帧，因此相似链不会把与最终代表帧没有直接相似关系的后续截图一并删除。应用建议只修改当前勾选，立即清除旧发送确认、候选和两类预警，不调用模型、不读取额外视频、不写工程；用户可以重新勾选任何截图，之后仍须再次检查并确认发送。

应用精简建议前，预警区显示预计减少的图片张数、JPEG 解码字节和口播字符，以及剩余图片数；应用后显示完整的精简前后负载对照。统计直接复用实际发送负载的本地计算，不估算模型 Token、费用或质量收益。关闭口播输入时，口播节省量明确为 0。

放行完全重复截图时，会话请求记录和最终人工动作证据回执保存一份确认凭证：确认时间、每组重复 SHA-256 和对应帧编号。下载的 v1 请求记录也包含完全重复和高度相似两类可选凭证并纳入 `recordsSha256`；独立验证器会检查确认时间不晚于请求发起时间，并确认分组或配对与请求帧指纹严格一致。旧版 v1 记录没有这些可选字段时仍可验证，但不会被补造为已经人工确认。

“本次会话模型请求记录”保留最近 100 次真正发往模型桥的调用，按新到旧显示会话序号、请求批次、发起时间、初次/补帧轮次、提供方、模型、图片数、图片字节、口播字符、成功/失败、错误信息和服务报告 Token。失败调用仍计入已发起请求与负载，因为服务端可能已经接收数据或产生用量；没有成功响应时不会补造 Token。预算或 Token 停止线在模型桥之前拦截的操作不进入请求记录。本记录只存在于当前面板会话，最多 100 条，不写工程，也不保存图片或口播正文。

用户可主动下载 `hyperframes-visual-request-log-v1` JSON。文件按实际调用顺序包含上述请求元数据和每张请求帧的编号、时间与 JPEG SHA-256，并对完整 `records` 数组的紧凑 JSON 计算 `recordsSha256`。导出时间不参与该哈希，因此哈希只表示记录段内容一致性；它不是签名，也不能证明模型服务实际处理了请求。导出不包含 JPEG、口播正文、API 密钥或端点地址。

同一区域可选择不超过 5 MB 的请求记录 JSON 做独立验证。验证器严格检查 v1 格式、顶层和嵌套未知字段、导出/请求/完成时间、唯一批次、严格递增会话序号、提供方/模型、初次/补帧轮次、1–12 张负载、帧数量/编号/时间/SHA-256、成功/失败与错误关系、Token 加总关系，并复算 `recordsSha256`。验证只返回记录数、失败数、带 Token 数和哈希；不会把文件导入当前会话、恢复候选或修改工程。

请求负载回执必须带非空批次号、有效发起时间，并满足单次 1–12 张、图片字节不超过请求上限、口播字符不超过逐帧上限总和、非负时间跨度和正整数会话序号。完整请求帧清单数量必须等于图片数，编号不能重复，每张新回执必须带 64 位小写十六进制 SHA-256；候选引用的每张证据图都必须以相同编号和时间出现在该批次清单中。“仅截图”回执中的口播字符必须为 0。可选 token 用量必须是非负安全整数，且合计严格等于输入与输出之和。旧版回执没有请求负载、帧指纹或 token 用量时仍可读取，并在界面明确显示缺失状态。

## 可选本机视觉模型

桌面版也支持显式配置的 OpenAI-compatible 本机端点，包括 Ollama 的兼容接口。系统不会自动探测、安装或下载模型；没有配置时，本机选项保持不可用。

启动桌面版前设置：

```powershell
$env:HYPERFRAMES_LOCAL_VISION_MODEL = "qwen3-vl:8b"
$env:HYPERFRAMES_LOCAL_VISION_BASE_URL = "http://127.0.0.1:11434/v1"
# 只有本机兼容服务要求认证时才设置：
$env:HYPERFRAMES_LOCAL_VISION_API_KEY = "..."
```

只允许 `localhost`、`127.0.0.1` 或 `::1`，防止把“本机模式”误配为远程上传。只设置模型名时，端点默认使用 `http://127.0.0.1:11434/v1`。模型必须支持图片输入和结构化 JSON 输出。

界面的“检测本机端点”只读取 `/v1/models`，不发送截图，也不触发模型推理。检测结果会区分端点不可访问、端点可访问但模型未找到、模型已找到。检测成功只证明服务和模型清单可访问，不代表视觉质量已经达标。

实际分析使用 `/v1/chat/completions`，仍只发送用户明确选择的最多 12 张低分辨率截图和对应口播。输出继续停留在当前会话的待审候选，必须回看、编辑并人工确认后才能进入动作索引。
