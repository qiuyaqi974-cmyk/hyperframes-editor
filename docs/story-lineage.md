# 版本与发布证据血缘图

入口：AI 助手 → 发布候选版本 → 版本与发布证据血缘图。支持放大查看、横向滚动和点击节点查看证据。

图从已有持久化记录派生，不增加第二份可漂移的图数据，也不修改方案或时间轴：

- 方案 provenance：父方案 → EDL/OTIO 外部导入 → 派生方案。
- 收件箱：来源文件、审核数量和拒绝理由；未保存导入显示独立待审分支。
- 选版记录：胜出方案 → 导演决定，附胜出/淘汰理由。
- RC：冻结快照中的导演决定 → RC；有渲染记录时再连接成片凭证。
- 发布观察：成片凭证 → 发布观察。平台导入会显示文件名、完整文件 SHA-256、数据行号、字段/单位映射和确认时间；人工录入明确标为不适用。
- 实验结论：两侧发布观察 → 人工确认的描述性实验结论，同时展示两侧观察、RC 和成片哈希。
- 导演学习：观察或实验结论 → 学习记录，展示支持/反例/背景角色、创作假设、来源确认时间，以及新鲜、衰减或过期状态。
- Brief 引用：学习记录 → 已应用到 Brief 的回执，展示实际应用字段、适用理由、引用角色与引用时的时效快照。

“当前工程”显示当前快照及当前 Brief 应用引用的完整上游证据。“选中 RC 冻结记录”完全读取该 RC 的历史快照，并显示绑定该 RC 的发布观察及其下游实验、学习和冻结时的 Brief 引用；即使当前打开另一工程，也不会用当前 Brief 补接历史。RC 存储仍沿用全局最近 12 条的既有机制，图中明确显示当前查看的工程和 RC。

旧记录可能没有选版绑定、平台映射回执或上游观察，父方案、RC、实验和学习记录也可能缺失。此时显示缺失/冲突节点和警告，不按名称猜测关系。重复 ID、重复发布观察、循环关系、哈希冲突、实验两侧不一致、学习凭证数量不一致和 Brief 引用漂移均显式标记。原始父方案不自动标为“曾胜出”，没有保存的历史选版理由不会被补造。成片凭证只表示记录存在，本视图不会重新读取成片文件，也不会修改观察、实验、学习、Brief、方案或 RC。

同时修复发布候选面板组装快照时漏掉 storyAssembly、storyAssemblyVersions、storyVersionSelection、externalClipInboxes 的问题；冻结前读取完整最新快照并重新检查门禁。原有 RC 保持不变，不回填不存在的历史数据。

验证：`npm run test:story-lineage` 覆盖方案分支、发布导入回执、实验两侧、学习角色/时效、Brief 字段、缺失、重复、冲突、循环、只读性、持久化和跨工程隔离。设置 `LINEAGE_CHECK_DIR` 到临时目录生成测试夹具，再启动本机 Vite（默认端口 5199），运行 `npm run test:story-lineage-ui` 检查节点点击、范围切换、完整证据链、放大视图及 RC 门禁。浏览器测试使用隔离的无头 Edge 环境。
