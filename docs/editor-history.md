# 多步撤销与重做

顶栏提供“撤销 / 重做”及可用步数。快捷键为 Ctrl/Cmd+Z、Ctrl/Cmd+Shift+Z，或 Ctrl+Y；焦点在输入框、文本域或可编辑内容时，保留浏览器原生文本撤销。

## 覆盖范围

文档历史覆盖导演目标与场景决定、原片粗剪与边界、全局结构、方案保存/恢复/选版、外部收件箱与派生保存，以及积木、素材引用、画布、字幕和配音时间轴。同步发生的一组写入（例如多段装配、恢复方案时更新多个原片与结构）合并为一步；一次指针拖动跨多帧也合并为一步。异步任务完成时的写入作为新步骤，不让长时间运行任务占据整个撤销事务。

撤销后再编辑会丢弃原来的重做分支。最多保留当前会话最近 50 步；快照共享不可变对象引用，不把数小时原片复制进历史。播放头、选择和播放状态不计入历史。

## 审核安全

- 历史跳转保留切点、结构和实际装配的块引用，但清除当前候选视觉结论、粗剪确认、结构确认、预演和已通过的当前场景审片状态。当前结构签名重新建立，仍须重新检查和确认。
- 尚未保存的收件箱批准退回待审，必须重新确认来源、边界和视觉；拒绝理由保留。已保存的审核记录与冻结方案内容不被改写。
- 撤销“新增方案”会使它暂时离开当前方案列表，重做恢复其原始内容；既有 RC 的独立冻结快照不受影响。
- 撤销/重做使旧的本地检查图缓存失效。预演、原片九帧检查、收件箱九帧检查和 EDL/OTIO 文件读取会检查工程修订号；期间发生编辑或撤销时，不把过期结果写回当前工程。
- 旧版“撤销上次配音”同样清除当前审核确认，防止绕过门禁。

## 会话边界

历史不写入工程 JSON、自动保存或 RC；刷新、导入另一工程、恢复 RC 后开始新的历史，不跨工程撤销。自动生成内容和应用配音时间轴属于当前工程编辑，可撤销。导出的文件、渲染进程、原片文件和 IndexedDB 中独立保存的 RC 不属于文档撤销范围。

## 验证

`npm run test:editor-history` 覆盖多步旅行、结构/边界/方案恢复、同步装配、拖动合并、分支、50 步上限、工程隔离、冻结证据、审核失效、收件箱与旧配音撤销。

启动 Vite 到本机 5199 端口后执行 `node scripts/test-editor-history-ui.mjs`，在隔离无头 Edge 中验证按钮、快捷键、重做分支、文本框和刷新边界；可通过 `HISTORY_TEST_URL` 修改测试地址。
