# 发布证据审计报告

发布候选面板中的“发布证据审计报告”用于把现有只读血缘和批次审计记录整理成可离线复核的 JSON 与 HTML。生成预览和文件不会修改工程、RC、发布观察、实验、学习、Brief 引用、批次会话或回滚回执。

## 使用流程

1. 选择“当前工程范围”或“选中 RC 范围”。
2. 点击“生成只读预览”。预览显示节点、关系、批次、回滚、异常数量、数据 SHA-256 和披露边界。
3. 检查缺失来源、重复 ID、哈希冲突、引用漂移和批次完整性提示。
4. 明确点击“下载审计 JSON”或“下载离线 HTML”。切换范围或选中 RC 后必须重新生成预览。

HTML 直接嵌入与 JSON 相同的报告对象，不访问网络。两种文件显示相同的 `evidenceSha256`，可用于确认它们对应同一份证据快照。

## 独立验证已有报告

在同一面板点击“选择审计报告验证”，可读取 `.audit.json`、普通 `.json`、`.audit.html` 或 `.html`。验证器只读取所选文件的文本：

- JSON 直接解析；
- HTML 必须且只能包含一个 ID 为 `publication-audit-data`、类型为 `application/json` 的数据块；
- HTML 中的脚本不会插入页面、不会执行，也不会加载任何外部资源；
- 支持报告 JSON 在数据块中使用安全 HTML 实体转义；
- 文件超过 10 MB 会被拒绝。

验证器检查格式、版本、哈希算法、规范化规则和未知关键字段，然后重新计算 `summary`、`privacyBoundary`、`lineage`、`batchSessions`、`batchRollbacks`、`issues` 六段的字节数与 SHA-256，最后复算整份 `evidenceSha256`。结果逐段显示“通过”“篡改或不一致”“缺失”或“不支持”，并显示文件类型、范围、生成时间、整份实际哈希和全部问题。

验证是纯只读操作。它不会自动修复报告，不会导入或合并证据，也不会写入工程状态或 IndexedDB。

## 两份报告版本差异

“两份已验证报告版本差异”区域分别读取左侧和右侧 JSON/HTML。每个文件必须先由同一独立验证器完整通过；任一侧篡改、缺段、版本不支持或包含未知关键字段时，比较按钮保持不可用。比较和每次下载前还会重新验证两侧报告。

差异按稳定 ID 比较血缘节点、血缘关系、批次会话和回滚回执；异常按固定分类比较。每项显示新增、移除、内容变化或完全相同，变化项保留字段路径、两侧结构化值和两侧 SHA-256。关系端点或标签变化表现为旧关系移除和新关系加入。预览明确显示两侧报告 ID、审计范围、生成时间和 `evidenceSha256`；范围不同时给出警告，不会把范围变化解释为效果变化。

只有两侧重新验证通过后才能下载同源 JSON 或自包含 HTML。五个稳定排序的数据段和整份差异分别保存 SHA-256；生成时间不参与差异哈希。差异报告只陈述证据结构变化，不推断因果、不自动选择更优版本，也不合并报告或写回工程及 IndexedDB。

### 独立验证已有版本差异

同一面板可选择版本差异 JSON 或 HTML 做纯只读验证。HTML 必须且只能包含一个 ID 为 `publication-audit-diff-data`、类型为 `application/json` 的数据块；上传内容不会插入页面、执行脚本或加载外部资源。安全 HTML 实体会在 JSON 解析前还原，超过 10 MB 的文件会被拒绝。

验证器检查格式 v1、SHA-256、`sorted-json-v1`、差异报告 ID、生成时间、左右报告 ID/范围/生成时间/证据哈希、范围一致性及既定字段。它分别复算 lineageNodes、lineageEdges、batchSessions、batchRollbacks、issues 五段的字节数与哈希，再按生成器相同的左右元数据、范围、摘要、声明、五段、警告和分段清单复算整份 `comparisonSha256`。验证结果不会修复或导入差异、导入两侧报告、合并证据或写入工程和 IndexedDB。

## 报告内容

- 版本、导演选版、RC、成片哈希、发布观察、实验、导演学习和 Brief 应用形成的节点与关系；
- 血缘构建器发现的缺失来源、重复 ID、哈希冲突、引用不一致和循环关系；
- 批次会话的文件名、文件 SHA-256、格式、模板 ID/名称、确认时间、状态和逐行证据摘要；
- 整批回滚回执、原因、时间和观察 ID；
- 活跃批次缺失观察、回滚覆盖不完整、跨会话重复归属、回滚后观察仍存在等批次异常；
- 各数据段的稳定 JSON SHA-256 和字节数，以及整份证据数据的 SHA-256。

生成时间不参与 `evidenceSha256`。输入数组会按稳定键排序，因此同一份证据即使读取顺序或报告生成时间不同，也会得到相同的数据哈希。

## 披露边界

报告不包含原片、代理视频、渲染成片、媒体二进制内容、转写全文、字幕全文或平台原始导出文件内容。本机渲染输出路径和渲染报告路径会替换为“已省略本机路径”。报告保留内容 ID、账号标识、人工理由、文件名和已有哈希，因为它们属于审计所需的结构化证据摘要。

报告不会重新读取媒体或平台文件，也不会把缺失关系推断为完整关系。异常节点和警告会原样进入离线报告。

## 验证

```powershell
npm run test:publication-audit
npm run test:publication-audit-diff
npm run test:publication-audit-diff-verifier
npm run test:publication-audit-ui
```

领域测试覆盖稳定排序与哈希、正常和已回滚批次、断链、重复、哈希冲突、回滚后观察复活、隐私边界、合法 JSON/HTML、HTML 实体转义、单段/总哈希篡改、缺段、未知字段和不支持版本。差异专项覆盖已验证门禁、相同、新增/移除/变化、字段差异、关系端点、批次、回滚、异常、范围不同、稳定哈希、JSON/HTML 同源和只读性；差异验证专项覆盖合法 JSON/HTML、HTML 实体、五段/总哈希/ID 篡改、缺段、未知字段、不支持版本、数据块/文件类型/大小门禁和输入不变。隔离浏览器测试覆盖先预览后下载、真实 JSON/HTML 验证、比较及差异再验证、篡改提示、恶意上传脚本不执行、全流程前后工程与 IndexedDB 证据不变，以及本机路径省略。
