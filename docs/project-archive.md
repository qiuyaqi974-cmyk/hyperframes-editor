# 工程归档与可移植恢复包

工程归档位于 AI 工作台的“工程归档与可移植恢复包”面板。它用于把一个可继续审查的 HyperFrames 工程及用户选择的独立证据保存为单个 `.hfarchive.json` 文件。

## 披露范围与依赖闭包

默认选择“最小披露”，只包含工程快照、外部素材引用和恢复所需元数据，不自动带出独立 RC、发布观察、实验、跨项目学习、批次会话或回滚回执。用户可以选择三个证据域：发布观察与实验、跨项目导演学习、批次会话与回滚回执。

点击“预览归档内容”后，系统才计算实际包含范围：

- 实验会要求两侧发布观察与 RC；
- 导演学习会要求其观察、RC，以及实验型学习的原实验；
- 活跃批次会要求逐行观察与 RC；
- 已回滚批次保留会话和回滚回执，但不会重新加入被撤销观察。

预览分别显示直接选择、依赖闭包额外加入、主动排除、敏感摘要类型和断链阻断。存在自动加入依赖时，必须明确确认“接受归档依赖闭包”才能导出。缺失 RC/观察/实验/会话、重复 ID、部分回滚或已撤销观察复活都会阻止导出。选择或证据在预览后变化时必须重新预览。

## 归档内容

- 当前工程快照；
- 独立发布候选 RC；
- 发布后观察；
- 平台批次导入会话与整批回滚回执；
- 人工确认的实验结论；
- 跨项目导演学习记录；
- 外部长视频引用清单。

归档不会复制长视频原片或代理视频。原片清单保存原始绝对路径、记录的文件大小、时长、分辨率、代理路径、转写来源指纹，以及桌面端可访问文件时计算的“文件大小 + 首尾各 1 MB”SHA-256 快速哈希。快速哈希用于发现离线和错版素材，不等同于完整文件哈希。

## 完整性清单

归档写入前会先转换为实际 JSON 形态，再用排序后的稳定 JSON 分别计算以下数据段的 SHA-256 和字节数：

- project
- releaseCandidates
- postPublishObservations
- postPublishBatchSessions
- postPublishBatchRollbacks
- postPublishExperiments
- directorLearning
- sourceReferences
- archiveMetadata（格式、版本、归档 ID、创建时间、工程名与恢复策略）
- disclosurePolicy（选择模式、请求域、实际包含/排除数量、依赖闭包和敏感摘要）

当前界面写出格式为 v3。导入时重新计算每一段，披露策略、批次会话与回滚回执分别校验。任一数据段不一致都会阻止恢复；不能通过修改清单外的显示字段绕过数据段校验。

旧的 v1、v2 归档仍可验证和恢复。v1 本来没有批次会话与回滚回执，系统不会补造；v2 是原有全量归档，没有披露策略。v3 导入预览会明确显示最小、自定义或全量披露，以及主动排除的证据域。主动排除不视为文件缺失或损坏。

## 恢复流程

1. 选择恢复包后只生成预览，不修改当前工程。
2. 预览显示数据段完整性、各类记录数量、原片绝对路径、素材离线/错版状态、同 ID 冲突和容量门槛。
3. 原路径离线时，可以逐条选择本地候选视频。预览并排显示归档值与候选文件的大小、时长和快速哈希；大小、时长或已有哈希不一致会阻止映射。归档没有快速哈希时明确降级为大小与时长核对。
4. 每条候选必须单独人工确认。已选择但未确认的候选会阻止恢复；没有选择候选的离线素材仍保留原路径并标记为缺失，系统不会自动搜索或猜测替代素材。
5. 真正恢复前会重新读取候选文件；候选在确认后发生变化、离线或凭证失配都会停止恢复并要求重新核对。
6. 确认后的新路径只写入恢复副本并保存独立映射回执。归档对象、归档内工程快照和原绝对路径保持不变；旧机器的代理路径不会带入已重定位素材。
7. v2/v3 会检查每个活跃批次的观察是否随包存在、每份回滚回执是否完整对应原始会话，以及观察是否跨批次重复归属。回滚后的批次若又携带旧观察，或本机仍存在该观察，会以“静默复活已撤销证据”为由阻止恢复。
8. 同 ID 不同内容会阻止恢复。合并后超过 RC 12、观察 100、实验 50、学习 300、批次会话 100 或回滚回执 100 的安全上限也会阻止恢复，避免静默删除本机记录。
9. 用户明确确认后，当前工程先保存为独立恢复检查点，归档本身也独立留存；归档工程以带日期的“归档恢复副本”名称打开。
10. 独立 RC 和证据只做无覆盖合并，并在同一个本机事务中写入观察、会话与回滚回执。相同 ID 且内容相同的记录视为已有副本；相同 ID 但内容不同的记录永不覆盖。

当前最多保留 20 个导入归档和 20 个切换前检查点。恢复包不会自动重新解释历史证据，也不会自动把学习经验写入导演 Brief。

## 只读恢复差异审计

归档完整性通过后，可以在恢复预览中生成“恢复差异审计”。生成时系统重新读取本机 RC、发布观察、实验、导演学习、批次会话和回滚回执，逐项标记新增、内容相同或同 ID 冲突；v3 披露策略主动排除的记录独立列出，不会被误报为损坏。报告同时计算合并后的六类容量，并列出原片引用的已核验、可用未核验、离线、错版或待确认重定位状态。

生成预览和下载文件都不会恢复工程、保存检查点、写入导入归档历史或合并独立证据。只有完整性通过的归档能生成和下载同源 JSON 与自包含 HTML。两种文件包含归档 ID、版本、披露模式、本机比较时间、逐项结构化摘要、记录哈希、容量、阻断和警告；六个稳定排序的数据段与整份审计均保存 SHA-256。冲突项不复制 RC 快照、媒体、平台原始文件、字幕或转写内容。

### 独立验证已有恢复差异审计

工程归档面板可选择恢复差异 JSON 或 HTML 做纯只读验证。JSON 直接解析；HTML 必须且只能包含一个 ID 为 `archive-restore-audit-data`、类型为 `application/json` 的数据块。上传的 HTML 不插入页面、不执行脚本或加载外部资源，安全实体转义会在 JSON 解析前还原；超过 10 MB 的文件会被拒绝。

验证器检查格式 v1、SHA-256、`sorted-json-v1`、报告 ID、归档元数据、比较时间和既定字段，再复算 collections、omissions、disclosureDomains、capacities、sources、findings 六段的字节数与哈希。整份 `auditSha256` 按生成器相同的归档元数据、比较时间、摘要、六段数据和分段清单复算。结果逐段显示通过、篡改、缺失或不支持，并显示实际总哈希。验证不会修复或导入报告，不会恢复工程、保存检查点、合并证据或写入导入归档历史和 IndexedDB。

### 两份恢复差异审计版本对比

分别选择左右恢复差异 JSON/HTML 后，每一侧必须先通过上述独立验证器；比较和每次下载前都会重新验证。预览显示两侧审计 ID、归档 ID/版本/披露模式、比较时间和 `auditSha256`。归档 ID、版本或披露模式不同时明确提示，不会据此判断哪份恢复方案更优。

对比按稳定键检查六类记录结果、主动省略、容量计算、素材状态，以及阻断与警告，逐项显示新增、移除、变化或相同。变化项保留字段路径、两侧结构化值和哈希。五个稳定排序的数据段和整份比较分别保存 SHA-256，可下载同源 JSON 与自包含 HTML。生成、比较和下载不恢复工程、不保存检查点、不导入归档、不合并证据或写入 IndexedDB。

### 独立验证已有恢复审计版本对比

工程归档面板可选择恢复审计版本对比 JSON 或 HTML 做纯只读验证。HTML 必须且只能包含一个 ID 为 `archive-restore-audit-diff-data`、类型为 `application/json` 的数据块；上传内容只按文本读取，不会插入页面或执行其中脚本。验证器拒绝超过 10 MB 的文件、未知关键字段和不支持的格式、版本或哈希规则。

验证器复算 records、omissions、capacities、sources、findings 五段的字节数与 SHA-256，并按生成器相同的左右审计元数据、归档匹配状态、总摘要、声明、五段数据、警告和分段清单复算整份 `comparisonSha256` 与报告 ID。界面显示左右审计及归档元数据、归档匹配结果、逐段状态、实际总哈希和具体问题；验证不会导入对比文件、恢复工程或写入任何本机记录。

## 验证

```powershell
npm run test:project-archive
npm run test:project-archive-disclosure
npm run test:project-archive-ui
npm run test:archive-restore-audit
npm run test:archive-restore-audit-verifier

npm run test:archive-restore-audit-diff-verifier
```

领域测试覆盖最小/自定义/全量计划、依赖闭包、拒绝依赖、断链阻断、v3 披露策略哈希与主动省略，以及 v1/v2 兼容；原有测试继续覆盖批次断链/重复归属/部分回滚/静默复活、篡改、容量、原片重定位和恢复副本。恢复差异专项测试覆盖 v1/v2/v3、新增/相同/冲突/主动省略、容量超限、素材状态、完整性门禁、稳定哈希、JSON/HTML 同源和只读性；恢复审计及版本对比验证器专项覆盖合法 JSON/HTML、HTML 实体、分段/总哈希/ID 篡改、缺段、未知字段、不支持版本、数据块/文件类型/大小门禁和只读性。隔离 Edge 测试覆盖默认最小预览、范围变更使旧预览失效、全量依赖确认、真实 v3 下载、v2 差异审计下载与独立验证、版本对比下载与独立验证、恶意 HTML 不执行、恢复及持久化合并。
