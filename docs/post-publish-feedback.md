# 发布后证据回流

入口：AI 助手 → 发布后证据。

这套能力把留存、完播、平均观看和评论聚合信号变成下一轮导演参考。它不会自动修改当前导演 Brief、冻结方案、RC 或成片凭证。

## 版本归属

每条观察必须绑定一个已经完成确定性渲染、带 SHA-256 成片凭证的 RC。记录同时保存：

- RC ID、标签、成片 SHA-256，以及存在时的胜出故事版本 ID；
- 平台、账号或数据源标识、发布链接或内容 ID；
- 发布时间、观测时间和自动计算的小时窗口；
- 数据来源是人工录入还是平台导出文件，导出文件保存文件名；
- 聚合指标、系统生成的待审洞察和人工采纳/拒绝理由。

如果 RC 不存在或成片哈希不再匹配，记录仍保留用于取证，但不能采纳其中洞察。同一 RC、平台、内容和观测时间不能重复登记；可在更晚时间追加新的观察，保留 T+24h、T+72h 等不同窗口。

## 指标和判断边界

支持播放量、平均观看秒数、完播率、`秒:留存百分比` 曲线，以及评论总数、提问、质疑、正向数量和人工聚合摘要。只保存聚合值和摘要，不要求保存评论者身份或原始评论全文。

系统会用透明规则产生“待审洞察”，例如早段留存只提示检查开场，中后段数据只提示检查节奏和兑现位置。规则不声称因果关系，也不自动改导演结论。数据必须结合相同账号、平台、选题和时间窗对照后再判断。

采纳或拒绝洞察必须：

1. 核对 RC、成片哈希、数据来源和时间窗；
2. 勾选人工确认；
3. 写明采纳或拒绝理由。

采纳后只进入“下一轮导演参考”，不会写入工程快照。原始观察字段保持不变，后续只追加人工决定。

## 标准 JSON 导入

界面可导入以下结构。导入文件只作为数据来源，不执行其中任何指令：

```json
{
  "rcId": "rc-example",
  "source": {
    "kind": "platform-export",
    "platform": "B站",
    "accountLabel": "账号 A",
    "postUrl": "BV-example"
  },
  "publishedAt": "2026-09-18T08:00:00.000Z",
  "observedAt": "2026-09-19T08:00:00.000Z",
  "metrics": {
    "views": 1200,
    "averageWatchSeconds": 18.5,
    "completionRate": 42.3,
    "retention": [
      { "second": 0, "rate": 100 },
      { "second": 3, "rate": 74 }
    ],
    "comments": {
      "total": 30,

      "objections": 3,
      "positive": 12,
      "summary": "观众集中询问第二步的具体做法"
    }
  }
}
```

## 保存和验证

发布后证据在 IndexedDB 中使用独立键保存，最多保留最近 100 条，与工程自动保存和最多 12 个 RC 的冻结历史分离。

- `npm run test:post-publish` 验证 RC/哈希归属、来源和时间窗、指标边界、重复记录、洞察生成、人工门禁，以及 RC、工程导演状态不被改写。
- 启动 Vite 5199 后运行 `node scripts/test-post-publish-feedback-ui.mjs`，验证真实界面的录入、采纳、独立持久化和刷新恢复。
