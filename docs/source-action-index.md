# 视觉动作索引

入口：AI 助手 → 长视频源素材台 → 视觉动作索引。

1. 引用原片，在原有播放器中设置入点、出点。
2. 播放圈定动作，必要时请求九帧辅助检查。每次检查最多 120 秒；没有后台全片扫描。
3. 填写主体、动作（必填）、对象、结果、景别、标签，选择动作/重点保留/明确不要。
4. 亲眼确认画面描述、来源和边界后勾选确认并入库。修改描述、区间或来源后需重新确认。
5. 按文字（空格分隔多个条件）、景别和决定跨原片检索。结果显示原片路径、毫秒时间范围、确认时间，可回看原片或请求检查图。

这是人工观察的结构化语义索引，不是自动视觉模型或向量相似检索。它不依赖转写，因此可记录无台词动作；不会把缺少转写当成已检测到静音。旧动作标记兼容按标签搜索，但不会被伪装成带结构化语义的记录。

## 保存与边界

- 记录存于 `sourceMedia[].eventMarkers[].semantics`，随工程 JSON、自动保存和会话撤销/重做保留；不保存媒体、检查图或播放器地址。
- 来源记录包含原片 ID、路径、大小、时长和尺寸的元数据签名，并绑定准确入出点。来源/范围变化或原片离线时标记失效，重新生成粗剪会跳过这些记录。签名不是内容哈希，无法发现同路径同元数据的内容替换；后续交接继续使用原有文件指纹验证。
- 每个候选保留 markerId。保存动作索引清除当前原片旧粗剪计划，用户需重新生成；已追加粗剪时禁止修改。不会追加时间轴、改写冻结方案或直接选为胜出版本。
- 新索引的人工语义确认不等于剪辑视觉通过：新候选仍需切点审核、结构预演和选版。逐词边界沿用原有向外吸附逻辑，索引仍标识人工观察边界。
- 搜索不读视频；检查图只在点击后请求，异步结果在工程变化、切换范围、卸载、撤销后被丢弃。最多显示 50 条结果，进一步缩小搜索可找到其余记录。
- 删除可使用同一原片上方的“无台词动作标记”列表。更正记录时删除旧记录，重新观察并保存。

## 验证

`npm run test:action-index` 覆盖人工确认、范围与来源校验、跨原片检索、来源过期、持久化、撤销/重做，以及索引确认和剪辑审核分离。

启动 Vite 5199 后运行 `node scripts/test-source-action-index-ui.mjs`，或通过 `ACTION_INDEX_TEST_URL` 指向测试服务。该测试使用隔离 Edge 和模拟媒体桥，验证真实界面的入库门禁、描述变化失效、跨原片检索/筛选，以及仅在点击后发送正确检查区间。未在该浏览器测试中执行真实本地视频解码；复用的桌面检查图引擎未修改。
## 模型辅助证据回执

通过视觉候选创建的人工动作记录会附带结构化 `visualEvidence`。索引界面显示单帧/跨帧、初次分析/补帧复核、提供方、模型、证据图数量、当次是否包含时间窗口播、模型可见证据、不确定性以及模型原始候选。跨帧回执还逐项保存相邻证据帧的起止时间、可见变化/可能变化/未见变化判断、证据、疑点和置信度。

如果新记录带请求负载回执，索引还显示唯一请求批次号、发起时间、它在当前画面索引面板会话中是第几次请求，以及完整请求的图片数、图片字节、口播字符和覆盖跨度。模型服务返回标准 usage 时，索引显示该次输入、输出和合计 token；没有返回时明确显示缺失，不用图片字节估算。可展开查看每张请求帧的时间、编号和 JPEG 解码字节 SHA-256；同一次模型调用返回的多条候选共享批次号。完整请求可能包含同批次其他候选使用的截图，因此图片数可以大于当前动作的证据图数量。验证会确认当前动作引用的每张证据图都属于该批次，并拒绝缺失或格式错误的新指纹与自相矛盾的 token 用量。旧记录没有指纹或用量时继续显示兼容状态。

如果记录来自补帧复核，回执还保存第一轮与第二轮模型原始结论的结构化对照。动作、结果、连续性或变化窗发生变化时，索引明确标记存在分歧；这只是复核提示，不代表第二轮更正确。

存在分歧的记录只有经过单独人工核对，重新确认完整视频区间后才能保存。动作索引显示核对时间；回执缺少对照、核对状态与分歧不一致或确认时间无效时会被拒绝。两轮一致时不会伪造分歧确认。

最终主体、动作、对象、结果、景别和标签仍来自人工确认字段。模型原始候选独立保存，便于识别人工修改和追查错误来源；回执不包含图片、口播正文、API 密钥或端点地址。纯人工创建的动作记录没有该回执，现有工程保持兼容。
